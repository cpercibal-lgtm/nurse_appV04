# Changelog

All notable changes to the AIGH Nursing Workforce Management System. Versions follow [Semantic Versioning](https://semver.org/); while the version is `0.y.z` the system is in development and runs demonstration data only.

## [Unreleased]

### Changed
- **A retried save can no longer be applied twice** (review fixes, 2026-10-17). On the 11 routes that take an `Idempotency-Key`, the change and the stored reply are now committed in one transaction, so a reply is never sent before the change is saved and a failure never leaves the change saved without its reply. A second request with the same key while the first is running gets 409 `IDEMPOTENCY_IN_PROGRESS`; a server failure rolls everything back and can be retried with the same key ([API.md](docs/API.md)). **Upgrade:** let requests finish before releasing; an unfinished record left by the previous version is refused until an operator checks it, because its change may already be saved.
- **Database failures answer 503 or 500, not 400.** A database that is down, busy or timing out now answers 503 `DATABASE_UNAVAILABLE` (try again), and any other unexpected database error 500, instead of 400 `INVALID_REQUEST`, which wrongly blamed the request. Duplicate, missing-record and data-rule errors keep their codes.
- **Contracts: date changes are for correcting typing errors, checked against the contract copy** (owner, 2026-10-15). The *Review date change* window has an *Open contract copy* button, and its text asks the approver to approve only dates that match the uploaded contract copy exactly. The wording no longer mentions a signed addendum, which is not needed. Behaviour is unchanged.
- **Contracts: change the dates of an approved contract, with approval** (owner request, 2026-10-15). *Edit dates* now also appears on Approved and Active contracts. There it sends a request (*Send for approval*) instead of changing the contract: the row shows the new dates waiting, and a different HR administrator opens *Review date change* to approve or reject it (a rejection needs a note); the requester can withdraw it. Approval re-checks what a contract approval checks (the new period still covers today, overlaps no other approved contract, and a longer contract needs valid credentials), then changes the dates, the Hijri dates and the status (Active or Approved by the new start) and re-evaluates eligibility. Suspending or terminating the contract withdraws an open request. New table `contract_date_changes` (migration `20261101090000_contract_date_changes`: one open request per contract; the decider is never the requester; a rejection has a note) keeps every request with the dates it replaced. API: `POST /contracts/:id/date-change`, `POST /contracts/:id/date-change/decision`.
- **Contracts: Edit dates** (owner request, 2026-10-15). A Draft contract's start and end dates can be corrected from the Contracts list (*Edit dates*), with a reason; the Hijri dates are recomputed and the change is audited from → to (`PATCH /contracts/:id/dates`). Only Drafts: a contract awaiting approval is returned to Draft first, and an approved or active one is renewed or terminated, never re-dated, so the second administrator always approves the dates that cover the nurse.
- **Nurses list: the row under the mouse is easy to see** (owner request, 2026-10-15). It turns brand green with white text (contrast 6.4:1), and the nurse that is open stays highlighted, so it is clear which row a click will open.

### Fixed
- **E-mail confirmation in a tab already open.** Opening a newer confirmation link in a tab that already showed the confirmation page did not confirm it, and a slower, older result could replace the newer one. Each link is now confirmed once, and only the latest result is shown (frontend tests with `jsdom`).
- **No more "client is already executing a query" warnings.** Prisma 7.10 sends some queries of one transaction at the same time ([prisma/prisma#29407](https://github.com/prisma/prisma/issues/29407)); `pg` 8 queued them with a deprecation warning that `pg` 9 turns into a failure. The database adapter now queues them itself (`backend/src/lib/prisma.ts`, [ARCHITECTURE.md](docs/ARCHITECTURE.md)), so the "`pg` 9 not yet usable" gap is removed from DEPLOYMENT.md §6. `backend/test/pg-concurrency.test.ts` fails if the warning returns.
- **Tests on Windows.** The exit-package test uses Windows' built-in `tar.exe` by its full path (from Git Bash, GNU `tar` comes first on PATH and cannot read the ZIP), test migrations run through Node, and the README lists what the backend tests need (a running PostgreSQL and a separate, freshly migrated test database). Unused exports removed.
- **Two dependency advisories** (`npm audit`, 2026-10-16). `fflate` 0.8.2 → 0.8.3 (moderate, [GHSA-px8p-9vwx-vf98](https://github.com/advisories/GHSA-px8p-9vwx-vf98)): `unzipSync` could loop forever on a malformed ZIP64 file, and **Import staff** unzips the uploaded spreadsheet with it, so a damaged file could freeze the browser tab. `source-map-js` 1.2.1 → 1.2.2 (high, [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)), a build-time dependency of Vite, not in the app bundle. `npm audit` now finds 0 vulnerabilities.
- **Docs still listed the Prisma CLI advisories as open.** The 4 high advisories in `mysql2` / `deepmerge-ts` were closed on 2026-10-04 by the root `overrides`, but DEPLOYMENT.md §6 still showed them as a gap before production and GITHUB_SECURITY.md as "known and accepted". The gap row is removed, GITHUB_SECURITY.md says when to drop the overrides, and the dated rows in CLEANUP_REPORT.md and V04_ARCHITECTURE_PLAN.md note the resolution.
- **Submit could do nothing when the browser wrongly reported "offline"** (found as the flaky WebKit department step in CI). react-query pauses a save while the browser says offline: nothing was sent, no message was shown, Submit kept its spinner until an "online" event. Safari / WebKit reports offline briefly and wrongly, so on a phone a save could hang. The app now always sends the request and shows the server's answer or "the server could not be reached" (`networkMode: 'always'`, decision D-1). A unit test covers it, and the smoke test now makes the browser report offline before Submit in every browser, with a failure message that says whether Submit was busy and what `navigator.onLine` was.

The migration sets **Passport** and **Resident ID (Iqama)** to every nationality except Saudi, and adds **National ID** for Saudi nationals only — National ID Number (encrypted and searchable like the Iqama number: new protected category `NATIONAL_ID`, with its processing-register entry for the DPO to review), Issue Date, Expiry Date (Gregorian/Hijri), card upload required, grace 0 days until HR sets it. Which units and positions require each type is still set under Requirements. Changing a nurse's nationality, or a type's setting, re-evaluates the nurses concerned at once. The hospital baseline file carries the same settings. API: `nationalityRule` / `nationalityCodes` on `POST`/`PATCH /credential-templates` (422 `NATIONALITY_RULE_INVALID`, `NATIONALITY_INVALID`); `optionalByNationality` on `GET /credentials/me/requirements`.

### Security
- **The VPS runs the images that were tested** (QA finding F2 / CICD-03, 2026-10-09). Deploy (VPS) used to rebuild the images after CI had tested a different build of them. It now builds them once, runs the same browser and release-path tests on those exact images (one shared action, `.github/actions/test-release-images`, used by CI too), and only then bundles them with a manifest (`ops/RELEASE_IMAGES`: commit, sha256 of `images.tar.gz`, image IDs). `deploy.sh load` refuses a tarball that is not the one the manifest names or a bundle without a manifest, before `docker load`, and appends each release's manifest to `/srv/nurseapp/image-manifests.log`. `ops/vps/test/run.sh` proves both refusals. No registry and no change to `nurseapp-release`; the deploy takes about as long as before, plus the browser tests (≈11 min).
- **Base and edge images are pinned by digest** (QA finding F2, second half; 2026-10-09). `node:22-bookworm-slim` (API and web builds), `nginx:1.30-alpine` (web), and on the VPS `caddy:2.8` and `clamav/clamav:1.4` are written as `tag@sha256:…`, so a tag that the publisher moves can no longer change what is built or pulled. - **Dependabot proposes only planned-safe versions** (owner, 2026-10-07): no new major versions of Node (Docker), `@types/node` or TypeScript, and no nginx mainline (odd minor) releases — these move on purpose, with testing ([docs/GITHUB_SECURITY.md §5](docs/GITHUB_SECURITY.md#5-dependabot)).
